Ghan Cinematic — AI Film Studio

A production studio that takes a story idea and returns finished shots. You write the script; the system breaks it into shots, locks each character's identity across every frame, and routes each stage to the provider you choose — a local GPU model or a cloud API — refusing to accept a render it cannot verify.

Overview

Most AI video work falls apart on the second shot: the face changes, the lighting resets, the character stops being the same person. Ghan Cinematic is built around fixing that one problem. Character references are generated once, stored, and re-applied to every shot as identity anchors, so a sequence reads as one continuous film instead of a slideshow of near-misses.

The second problem is dependency. A studio that only works on your GPU is slow and hardware-bound; one that only works through a single cloud vendor dies the moment that vendor has a bad day. Ghan Cinematic is built as neither. Every stage has its own provider slot — script analysis, keyframes and video are routed independently, and any slot can be pointed at a free browser session, a paid API, or a model running on your own machine. You can start a project on a local model, switch the video slot to Veo for the hero shot, and drop back to Qwen for the rest, without changing the workflow around it.

Where it runs

Ten providers are registered behind one interface. The choice is per stage and can be overridden per shot.

  • Local GPU — ComfyUI running Qwen Image 2.1 on your own card. No key, no credits, no rate limit; one render at a time. Ollama covers local language models for script work.
  • Free browser sessions — Grok and Google Flow driven through the browser, so no API key is required at all.
  • Paid APIs — xAI Grok, OpenAI, Google Gemini (including Veo 3.1 video) and Replicate (FLUX, Stable Diffusion 3.5, MiniMax, WAN 2.1).
  • OpenAI-compatible gateways — KiloCode and OpenCode, for routing text through a single key across many models.
  • Mock — a zero-credit dry run that exercises the whole pipeline without spending anything.

Model lists are discovered live from each provider's endpoint, with pricing pulled in so the routing dropdowns can mark what is free and what costs money.

How the pipeline runs

  1. Script ingest. Write or paste the script; the system parses scene intent, tone and continuity requirements.
  2. Shot breakdown. The script is split into ten-second shots, each with framing, camera move and continuity notes.
  3. Asset build. Characters, locations and props are extracted into their own studios, each with a reference sheet.
  4. Identity lock. References are filtered per scene — only the characters actually in a shot are attached, tagged so the model knows which face belongs to which name. Face, hair and accessories are locked; only wardrobe changes.
  5. Keyframes. Each shot's still is generated through the image slot — local Qwen or any cloud image model.
  6. Motion. Each keyframe is animated through the video slot, with a per-shot override when one shot needs a different model.
  7. Compile. ffmpeg stitches the shots in timeline order and mixes the selected score under them.

Guard rails

Browser automation is fragile by nature: a failed capture can save a screenshot of the UI instead of the generated frame, and the pipeline would happily animate it. Every asset is therefore validated before it is accepted — real image magic bytes, a minimum long edge and a minimum file size. A thumbnail or a cropped screenshot of the page is rejected and the shot is retried rather than passed downstream.

Shots fail individually, not as a batch. A bad frame is re-rolled on its own, and the rest of the sequence is left untouched.

How it's built

The studio is developed under a review gate that is written into the repository rather than left to discipline. Every change faces four specialist reviewers before delivery — an architecture reviewer, a bug hunter, a product reviewer and a regression-safety reviewer — on top of a typecheck and test gate. A result carrying an unresolved REVISE verdict cannot be presented, and the gate exits non-zero when one is outstanding.

What it does well

  • Character identity stays stable across an entire sequence, not just a single frame.
  • Ten providers behind one interface — swap the route per stage, or per shot, mid-project.
  • A local escape hatch: when a provider is down or out of credit, ComfyUI and Qwen keep the pipeline moving.
  • Per-shot re-renders, so one bad frame never costs you the whole film.
  • Every captured asset is validated — a screenshot of the UI is caught and retried, not animated.
  • A built-in assistant that performs real actions — changing the image provider or running a step — rather than just describing them.
  • Timeline editor, shot library, credit meter and social caption export in the same tool.

See it in action

One project, start to finish. Click any screenshot to see it full size.

01

Start a project

The whole studio is one page — Story Creator at the top, then characters, locations, props, production notes, generated scenes, the pipeline bar and the final clip. No wizard, nothing hidden behind a next button.

02

Route the providers

Text, image and video are three separate slots, each with its own provider and model. Any slot can point at Grok in a browser, a cloud API, or a local Ollama model — and the same panel holds the API keys.

03

Set the story and its shape

Tone, structure and length are constraints, not decoration — they are injected before the model writes a single word. This run: Nostalgic, Contrast / Two Worlds, 60 seconds, in English.

04

Generate the script

The script lands in Step 0 and stays fully editable. Every beat is written as something the camera can see — no interior monologue, no explaining what a character feels.

05

Extract the cast and the sets

Characters and locations are pulled out of the script with reusable descriptions. This is the text that becomes the identity reference later, which is why it is editable before anything is rendered.

06

Generate the references

Each character gets a three-view sheet on a neutral background, each location a plate — generated from the descriptions above. These are the files every shot prompt attaches as its identity and set anchors, which is why the same face holds from shot one to shot six.

07

Compose the shot

Nothing here is left to the prompt to guess. The location binds that set's plate, the character chips attach only the identity sheets for the people actually in this shot, and the prop tags name the objects that must stay consistent. The shot composer sets framing, angle, lens, lighting and movement explicitly — then the image prompt is assembled from all of it, and the video prompt is written out in the technical format underneath: subject and action, camera movement, environment FX, style.

08

The prompt writes itself

The composer's choices resolve into a single image prompt — subject, wardrobe, set, lighting, lens — assembled automatically from the location, the character sheets and the prop tags, then left editable. Nothing about the shot stays implicit.

09

The shot renders

The keyframe comes back and opens full size in the app. Both characters in the same frame, the SOLD sign in the window, the box marked MARA — BEDROOM — all of it carried in by the references rather than described again.

10

Multi-Shots

One click returns nine consecutive frames of the same shot as a 3×3 grid — KF1 to KF9, identity held across every panel. Pick any cell and it is re-rendered at full resolution as its own keyframe, so you choose the moment instead of re-prompting for it nine times.

11

Pick a frame, animate it

The grid is a picker. Choose a cell and it comes back as a full-resolution keyframe, filed under Extracted Shots with the cell number stamped on the thumbnail — then it animates like any other shot. The clip underneath is that panel: six seconds of motion out of one still.

12

Render and compile

Keyframes go through the image slot, each one animated through the video slot, then ffmpeg stitches the shots in timeline order and mixes the score. Shots fail individually — a bad frame is re-rolled on its own.

The 60-second cut

Six shots, ten seconds each, animated from their keyframes and stitched in order — the whole piece, generated and assembled by the pipeline.

The six shots

One project, generated end to end — a 60-second piece called The Room We Left, built on Contrast / Two Worlds. Same room, same two people, two time periods. The woman carries the same face through every shot she appears in.

References & sets

The character sheets and location plates the shots were generated against — three views per character so identity holds from any angle.
